## 3. 一条 run 的代码路径

```
RunEnv.reset()                          run.py
  ├─ acts.random_act_list(Rng(seed,"act_selection"))    第一幕是密林还是暗港
  ├─ mapgen.generate_map(seed, act, act_index=0)        地图（act_{n}_map 专用流）
  ├─ _populate_relic_bag() / _preroll_all_contents()    隐藏区：内容预掷（L3）
  └─ RunState(acts=…, act=1, map=…, hidden=…)

RunEnv.step(action)                     run.py
  ├─ PHASE_MAP   → reachable_nodes → _enter_node(node)
  │                 ├─ kind == unknown → pointodds.roll() 进房间才掷（含概率累计）
  │                 ├─ monster/elite/boss → core.start_combat(…)
  │                 ├─ treasure/shop/rest_site/event → 对应房间
  ├─ PHASE_COMBAT→ core.step() → 胜利后 _sync_player_from_combat()（唯一回写入口）
  │                 └─ boss → 非最终幕：给奖励后 _begin_act(act+1)：末幕：PHASE_WON
  ├─ PHASE_*（奖励/营火/商店/事件）→ Run 层结算
  └─ 观测：observe.observe_run() / observe(combat) → _Step → RunBot
```

当前神经训练链路是 `SpireEnv → Observation → featurize.encode_observation → sts2_rl.nets`。
RunObservation 的统一神经编码仍属规划，不能将上面的 RunBot 流程描述为已有整局神经训练。
两条环境入口的角色上下文与观察一致性问题见 [2026-09-22 架构复核](15-架构复核-2026-09-22.md)。

**信息边界落在结构上**：`RunHidden`（`node_contents` 与 `point_odds`）只有
`_enter_node()` / `_roll_unknown_room()` 能读；`observe.py` 是唯一投影出口，
`test_anticheat.py` 用 AST 扫描确认策略模块**在语法层面**够不到它。

## 4. 最小可运行示例

```python
from sts2_sim import RunEnv, RunBot

env = RunEnv(seed=7, attempt_budget=64)
bot = RunBot()
step = env.reset()

while step.phase not in ("won", "lost"):
    action = bot.act(step)
    step, reward, done, truncated, info = env.step(action)
    if done:
        break
    if info["hp"] < 20 and env.attempts_left:
        env.restart_node()      # ⭐ 回到本节点开头：同一副牌序、同一份奖励
```

战斗层单独跑（固定遭遇、无 Run 层）：

```python
from sts2_sim import SpireEnv, RuleBot
env = SpireEnv(seed=0, attempt_budget=0)      # K=0 = NoSL 对照
obs, info = env.reset()
obs, reward, done, truncated, info = env.step(RuleBot().act(obs, info["legal_actions"]))
```

### ✅ 有测试守住（结构层）

| 性质 | 测试 |
|---|---|

### ❌ **没有**证明（诚实声明）

| 事项 | 为什么没证明 |
|---|---|
| 数值与真机一致 | **真机对拍 = 0**。`verify_implemented.py` 比的是"引擎 vs 自己的源码抽取"，只能证明管线没改数字 |

| 执行帧栈 | 嵌套选择 / 事件内战斗尚未被统一表达（审计 F09 未完部分） |
| SL 的语义前提 | 需要你真机跑 `tools/saveload_probe.py`（`docs/01` §1.8） |
| 训练有效 | 还没有"胜率提升"的声明；训练侧只修了协议与门禁 |
| 吞吐够用 | 以 `train_combat.py` 打印的实测值为准，不沿用旧文档的目标值 |

### A.1 那个"怪物打自己"的 bug（值得单独记一笔）

**症状**：区分度测试发现随机策略也 100% 通关 —— harness 完全没有区分度。

**根因**：`core._apply_effects` 把效果目标**永远解释成"敌人列表里的某一个"**。
怪物攻击时 `target_index=0` 指向 `state.enemies[0]`，于是怪物打的是自己；
红虱的"施加虚弱"也施加给了自己。玩家因此永不掉血。

**为什么 22 个测试都没抓到**：它们断言的全是"不变量"（HP 非负、卡牌守恒、能跑完）
和"基线能赢"。怪物自己打自己完全满足这些断言。

**抓出它的那条测试**：

```python
# 随机策略不该和规则 bot 打平
self.assertGreater(rule_floor - random_floor, 2.0)
```

**教训**：一个只能证明"程序没崩"的测试套件，价值接近于零。
**测试必须能分辨好坏，而不只是分辨对错。** 这条现在体现在
`test_runbot_baseline.py` 与 `healthcheck` 的"区分度"检查里。

### A.2 骨架期的其它历史数字

* 完整 run 吞吐 19.9 局/秒、3,656 决策/秒；单场战斗 15,889 步/秒。
* 基线 bot 通关率（K=1）26.2%、平均第 8.0 层（地图 16 行）。
* 区分度：规则 bot 27% / 平均 7.2 层 **vs** 随机策略 0% / 平均 1.8 层。

> 这些数字来自**骨架期内容**（12 张卡）与**旧地图**（16 行固定权重网格），
> 与当前实现不可比。要当前吞吐/胜率，跑 `train_combat.py` 与
> `tools/healthcheck.py`。
