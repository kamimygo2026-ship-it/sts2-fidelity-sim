## 2. 分类器应提供线索，不能直接发准入证书

### 2.1 继承必须展开

[AnticipatePower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/AnticipatePower.cs) 只覆写来源，但继承 [TemporaryDexterityPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/TemporaryDexterityPower.cs)；[DarkShacklesPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/DarkShacklesPower.cs) 继承 [TemporaryStrengthPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/TemporaryStrengthPower.cs)，并改变正负方向。

父类实现施加时修改力量/敏捷、层数变化时同步属性、所属参与者侧结束时移除并还原属性。因此“本类没有 hook”不等于没有行为，也不能统一成随便一个回合末减层数。

近期算法：建立类→父类索引，按继承链得到有效成员，记录覆写遮蔽和显式 `base` 调用；再收集字段读写、命令和外部消费者。复杂 C# 无法判断时标记待人工确认，不输出“纯数据”。临时属性家族可用一个明确的手写实现复用，仅把属性类型、符号和来源作为参数；仍要保留父类的回调条件和顺序。

验收：首次施加与追加层数、正向与负向、玩家与敌人侧结束、叠加其它属性变化分别对照源用例。继承行为缺一个环节时，全家族对应变体不能通过准入。

**状态（`docs/12` §2.28 之后）**：本族 21 个子类已按上述方案落地 ——
`sts2_sim/powers.py` 的 `_TEMPORARY_ATTRIBUTE_POWERS` 一张表 + 一份实现
（属性类型 / 符号 / 来源作为参数），父类的三条回调（`BeforeApplied`、
`AfterPowerAmountChanged`、`AfterSideTurnEnd`）条件与顺序逐条照抄，没有简化成
"回合末减层数"。上述四类验收场景分别落在
[tests/test_temporary_attribute_powers.py](../tests/test_temporary_attribute_powers.py)，
另加一条"源码里的同构子类全集 = 引擎表"的族完整性检查。
⚠️ §2 开头要求的**分类器改造仍未做**：`docs/14` 里的继承展开与"纯数据"标签还是旧口径，
本族是靠人工逐项核对源码落地的，不是分类器给出的结论。
**同一个坑在 `docs/12` §2.29 又踩了一次**：那批"只覆写 ``Type``"的名单同样是错的
（`biased_cognition` / `debilitate` / `no_block` 等其实都覆写了事件方法或提供了被别的
能力调用的公开方法）—— 所以 §2.1 要求的"再收集字段读写、命令和外部消费者"不是可选项，
只看 override 的扫描结果不能用来排期。

### 2.2 “已具备”“待实现”“范围外”分开

[gap_clusters.py](../tools/gap_clusters.py) 的 `buff_waves` 当前把 `POWER_PLANNED_SLOTS` 合并进 `ok`；`power_groups` 只扫描当前类文本，并通过 `GetTeammates / GetPlayerName / NetService` 标记多人。这些只能作为人工检查提示。

修订后的分类状态：

| 状态 | 必要证据 | 能否进入训练范围 |
|---|---|---|
| 可直接填充 | 全部所需原语及状态生命周期已经实现；完整行为仍待落地 | 否，内容本身还需验收 |
| 缺基建 | 缺具体命令、查询、状态或执行阶段，列出阻断链 | 否 |
| 待判定 | 继承、动态池、间接消费者或源码条件尚未解释 | 否 |
| 范围外 | profile 明确不包含，且有内容元数据或可达性证据 | 不计入该 profile 的待做分母 |
| 已验证可用 | 行为闭包完整，并通过指定级别的验证 | 仅进入相应等级的训练范围 |

出现玩家名可能只是显示；`GetTeammates` 也需要确认接收者和集合语义。不能凭关键词断言单人恒等。全文未搜到施加者只能形成“疑似不可达”，还需核对工厂/注册表、随机池、初始能力、存档入口。真正范围外应记录理由、版本和 profile，后续版本变更时重新检查。

生成器近期不必改成完整 C# 编译器：先补继承索引、显式的人工确认记录和否定默认值。若正则无法稳定识别结构，再引入 Roslyn 做静态结构分析；分析器不进入 step 热路径。生成报告保留所有 blocker，主因仅供展示；收益按去重后的完整依赖闭包计算，不能把同一张牌重复计入多个槽位的“解锁数”。

`docs/14` 是生成文件，应修改生成器后重新生成，不能手改报告。本轮只修订规划，没有修改该工具，旧报告中的分类和成本需按本文复核。

## 3. 能力实例：先解决身份，再填复杂能力

当前 [Combatant](../sts2_sim/core.py) 有 `powers / power_vars / powers_applier` 等以 pid 为键的状态，足够表达许多简单计数能力，但不能自然表示同一 pid 的两个独立载荷。

[NightmarePower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/NightmarePower.cs) 明确使用 `Instanced`：选中牌先克隆并清除苦痛，保存在该能力自己的数据里；下次抽牌前按层数再克隆，最后移除该实例。[HeistPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/HeistPower.cs) 和 [SwipePower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/SwipePower.cs) 同样声明 `Instanced`。

最小设计是引入能力实例记录，字段按首个用例添加：实例 id、pid、owner、applier、target、amount、类型化 payload、顺序信息。payload 先支持 Nightmare 的卡快照和 Swipe 的被偷卡引用，不引入任意脚本对象。`StackType` 决定层数语义，`InstanceType` 决定是否合并；二者不能混为一谈。

普通计数能力保留现有查询接口，但底层只有一份权威状态。可以分阶段迁移，不能同时维护两套可独立写入的层数。读取某个 pid 的聚合值、枚举实例、删除指定实例要分成明确操作，聚合规则以消费者源码为准。

实例引用随 snapshot 一起恢复，禁止保留指向旧状态树的活对象；对外观察使用局部实体引用和可见数据。内部唯一 id 不作为模型特征。

验收：两个 Nightmare 分别选择不同实例；复制牌保留该保留的属性并清除源码明确清除的属性；只移除已触发实例；两次偷牌能独立归还；任一选择边界存取后结果与连续执行一致。

## 4. 伤害、死亡与 Run 结算需要分别建模

### 4.1 Buffer 的前置是伤害阶段，不是完整 Osty

[CreatureCmd.Damage](../data/decompiled/sts2/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:259) 即使没有 Osty，也会调用前后生命损失阶段。[BufferPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/BufferPower.cs) 使用 `ModifyHpLostAfterOstyLate` 把自身目标的生命损失变为零，再在相应回调消耗层数；多人缩放在单玩家时是恒等。

应先定义源码对应的管线：伤害修正及通知 → 受击前通知 → 格挡 → BeforeOsty 普通/Late 及通知 → 未格挡伤害目标重定向 → AfterOsty 普通/Late 及通知 → 扣血 → 必要的溢出回流 → 伤害结果、触发和死亡流程。没有宠物时，目标重定向保持原目标，仍执行各伤害阶段。

不能把所有“修正后”通知统一推迟到扣血之后。参与修正者、普通与 Late 的顺序、截断比较要逐阶段对照 [Hook.ModifyHpLost](../data/decompiled/sts2/MegaCrit.Sts2.Core.Hooks/Hook.cs:1725)，不能自行假定所有阶段共用相同的消费判据。

验收先做无宠物的 Buffer：零伤害、完全格挡、先被其它效果减为零、正生命损失、多段命中。之后做 Osty 重定向与溢出回到原目标时再次经过后置阶段的用例。直接 LoseHp 与攻击伤害也要分别按其源码入口验证。

### 4.2 Heist/Swipe 必须连同经济与永久牌组交付

Heist 死前加入金币奖励并标记归还历史。Swipe 偷牌时移除原永久牌；死前把同一永久实例加回，再添加特殊卡牌奖励并记账。后者不能按一般选卡奖励再加一张牌。

因此“在 mark_dead 加 BeforeDeath hook”只是入口，不是完整实现。需要：能力载荷、战斗所依附的 Run 上下文、永久实例引用、额外奖励容器、奖励领取语义和地图历史。

近期沿用现有 Run/Combat 状态，增加必要的明确命令和结算记录即可，不建设数据库事务系统。每个效果的执行位置和已完成标记纳入执行帧/snapshot；在同一次恢复后的执行中，死亡与归还只执行一次。SL 恢复到偷牌前应恢复牌组和奖励，恢复到偷牌后应保留被偷关系。

验收：死亡归还、逃跑、战斗结束、重复死亡通知、多个被偷实例、无永久牌关联的生成牌、领取特殊奖励不重复入库、SL 后完整轨迹一致。逃跑和胜利条件不能擅自复用死亡结算。

## 5. 卡牌修改、附魔和 Forge

### 5.1 附魔是有生命周期的行为对象

[EnchantmentModel](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models/EnchantmentModel.cs) 有状态、挂载卡、准入查询、监听资格和出牌行为。[Swift](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Enchantments/Swift.cs) 仅在 Normal 状态触发，先 Disabled 再抽牌；[Clone](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Enchantments/Clone.cs) 自身没有方法，行为由营地克隆选项消费。它们分别证明“永久标签=静态数值修正”和“空类=无行为”均不成立。

设计需区分永久实例上附魔的类型/量与战斗副本上的运行状态，并逐类型确认复制、重置、替换和叠加规则。有效费用、关键字、目标类型、次数与数值从统一查询生成；挂载前检查允许牌型和现有附魔。苦痛与附魔保持独立语义，复制操作由具体源码定义保留矩阵，不能统一全拷贝或全清空。

最小交付选择一个数值附魔、Swift 和 Clone：覆盖数值查询、一次性出牌触发、战斗外消费者三种行为。验收包括两张同名不同附魔、抽牌触发嵌套选择、SL 恢复触发状态、跨战斗重建状态、营地选项过滤和永久回写。

### 5.2 Forge 是多步骤命令

[ForgeCmd](../data/decompiled/sts2/MegaCrit.Sts2.Core.Commands/ForgeCmd.cs:31) 查找未消耗的非 dupe SovereignBlade；没有则造牌加入手牌；提升伤害时又扫描包含消耗堆的非 dupe 剑，再执行每张牌的 `AfterForged` 和全局 `AfterForge`。因此“只给手中某一张剑加伤”不够，“有消耗剑就不再造剑”也不对。

第一批契约：显式卡实例成长值、生成来源和 dupe 语义；按源码定义集合范围；造牌、满手牌去向、每牌更新与全局通知的顺序。动态目标/格挡通过统一查询读取 Parry、SeekingEdge 等消费者依赖，参照 [SovereignBlade](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Cards/SovereignBlade.cs)。

验收：无剑、多剑、只有消耗剑、同时有普通剑与 dupe、满手牌、升级/复制后成长、AfterForge 触发顺序。完整 Forge 仍可随 Regent profile 开放，契约先定，不必为此暂停铁甲内容填充。

## 6. Osty 与额外回合

### 6.1 Osty 不是加入 enemies 的另一只怪

[OstyCmd.Summon](../data/decompiled/sts2/MegaCrit.Sts2.Core.Commands/OstyCmd.cs:34) 区分首次召唤、已存活时增加最大生命、死亡后复用旧实体复活，并记录召唤历史。[DieForYouPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/DieForYouPower.cs) 定义代主人承受符合条件的攻击、死亡后保留实体和保留该能力。

最小实体契约包含阵营、pet_owner、稳定引用，以及存活、可命中、是否离场三个独立判断；不以 `hp > 0` 代替全部生命周期。允许死亡实体留在状态中，复活继续引用原实体。召唤量、最大生命和当前生命的变化按命令区分，不把召唤等同于治疗。

伤害还涉及主人格挡、宠物承伤和 overkill 回流，必须复用 §4 的阶段。最低组合为 Summon + DieForYou + 死亡保留/复活 + 观察/目标查询，再逐个加入 Calcify、NecroMastery 等效果。验收包含死亡后合法目标集合、首次/再次召唤、死亡后再召唤、源实体关联、历史计数和溢出伤害。

### 6.2 额外回合要接入调度

[CombatManager.SwitchFromPlayerToEnemySide / SwitchSides](../data/decompiled/sts2/MegaCrit.Sts2.Core.Combat/CombatManager.cs:1819) 先查询额外回合参与者，再切换侧别并回调；额外玩家回合不按普通新一轮的分支递增 RoundNumber。

使用现有执行帧增加可序列化的回合阶段和参与者信息，按源码驱动 start/end/清理/切侧，而不是额外调用一次整个 `end_turn/start_turn`。隐藏显示属性不代表无规则作用。验收要比较能量、抽牌、格挡、持续效果、敌人行动次数及回合/历史计数；SL 在阶段边界不重复清理或多执行敌人回合。

| C6 角色扩展 | 完整 Forge、Osty、其它角色资源及额外回合 | 对应 C1/C2/C4；无需其它角色全部完成 | 每角色独立 profile、观察和行动覆盖 |

C2/C3/C4 不构成整批串行链。集合公式不需要等待所有条件遗物，普通 Run 队列也不需要等待所有事件。C5 可以先贯通一个明确受限范围，但必须标注分布变化，不能把缩池课程当作完整原版整局。

Ancient 的界面台词可省略，选项生成和后果不可省略。[Neow.GenerateInitialOptions](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Events/Neow.cs:216) 包含条件分支、随机抽取和池裁剪。先实现所选 profile 所需的起始事件流程和选项依赖，随后扩张；完整原版范围则必须覆盖其所有可达选项，不能运行时遇到未支持选项就重新抽。

遗物、药水、事件不各建一套效果引擎：按“查询/计数”“立即命令”“选择与续执行”“跨房间持久状态”“角色机制”映射到上述批次。每项保留自身触发入口、支付代价、候选池、获取/移除语义和失败条件。仅共享命令原语，不能因为都能加力量就跳过不同的生命周期。

怪物内容继续按行为状态机验证：当前意图可观察，不代表未来转移固定；加权随机、历史限制、阶段切换、召唤和复活仍按源码执行。此项是对数值模拟训练假设的约束，无需读取整局 RNG 给策略。

## 8. 技术栈、训练边界与交付门槛

近期继续用 Python dataclass/明确手写处理器/受限效果表示，以及已有测试和训练栈。不为长尾内容提前重写 Rust/C++，不建设完整 C# 解释器，不以新增网络规模代替缺失游戏机制。静态分析与内容编译在训练前执行，训练 worker 使用冻结注册表；性能优化以完整 step/clone/search 的实测剖析为依据。

先保证能力实例、卡牌成长/附魔、宠物、选择和额外回合的可见部分能进入 observation 与候选动作。模型沿用实体编码、历史记忆和候选动作评分，新增可见实体时扩展 schema/编码器；不把内部 payload 中尚未公开的信息自动输入模型。

允许 SL：模拟器保存真实隐藏 RNG 用于环境恢复；策略只持有公开观察及实际尝试过的历史。规划搜索使用从可见信息建立的随机状态/信念采样，不能克隆带真实隐藏 RNG 的环境来免费预演。真实尝试获得的信息可保留，但恢复后执行最佳结果必须实际重放动作，并计入重开预算。

课程按机制闭包逐步扩张；每次记录 source/version、规则版本、profile、观察/动作版本、内容池和重开预算。新内容不能在一次训练运行中静默热更新。缩池课程、完整范围评估、允许 SL 和不允许 SL 的结果分开统计；机制缺失导致的 unsupported 单列，不能当普通输局或从分母中无记录消失。

每批内容的完成条件：

1. **源码依据**：有效继承成员、调用者/消费者、状态生命周期和随机池已解释；无法解释的分支显式阻断。
2. **规则证据**：独立人工源用例覆盖正常、边界和组合场景；不能只用生产抽取器生成的期望值验证自身。
3. **恢复证据**：连续执行与决策/阶段边界恢复后执行的状态、轨迹、奖励和 RNG 消耗一致。
4. **入口证据**：抽到、生成、复制、转化、商店、事件、初始配置和召唤等适用入口全部使用同一范围约束。
5. **模型证据**：可见的新增机制能编码，合法动作可表达，接口版本和词表已同步。
6. **保真等级**：源码用例通过与真机对拍通过分别记录；通过前者不声称已达到后者。
