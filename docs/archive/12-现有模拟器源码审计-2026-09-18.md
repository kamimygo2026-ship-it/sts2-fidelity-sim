# 12 · 现有模拟器源码审计

审计日期：2026-09-18。对象：当前工作区的 `sts2_sim/`、`sts2_rl/`、训练入口、测试、内容数据与本地反编译 C# 源码。

本报告对应本次实际读取和运行的代码，不沿用旧文档里的完成率。这里只分析并规划，不修改模拟器实现。后续方案见 [完整模拟器规划](D:/桌面/尖塔模型/docs/13-完整模拟器与训练实施规划.md)。

## 1. 结论与需求基线

当前项目已经具备有价值的 Python 原型：数值战斗内核、数据导入与源码抽取、怪物状态机解释器、效果与能力处理、选牌挂起、Run 房间流程、观测投影、SL 快照、实体 Transformer 和战斗 PPO。建议在现有基础上修正关键接口，逐步收敛到可信模拟器。

但它还不能作为“与真实游戏语义一致的完整训练环境”。问题不仅是缺少卡牌：状态在系统交接中丢失，训练入口与内容门禁没有闭合，模型遗漏影响决策的公开信息，部分源码条件没有进入运行时，地图和整局生成仍然近似。继续长时间训练可能把这些偏差学进模型。

按用户最新确认，**允许重开是正式需求**。模型可以记住此前试次中实际观察到的信息，但不能读取种子、隐藏牌序、未来掉落或 RNG 状态。SL 与直接读取未来结果必须保持区别。NoSL 只作为评估对照，不替代正式 SL 目标。

“保留最好的一次结果”可保留为训练模式；接入真实游戏时，要通过游戏实际支持的存档恢复和动作重放兑现该结果。当前内存快照还没有证明这种部署等价性。

本次审计是跨模块审查和针对性复现，不是全部卡牌、敌人、事件的逐条认证；没有启动真实游戏或执行真机对拍。

## 3. 应优先处理的问题

以下 P0 表示阻止可信的大规模训练；P1 表示阻止完整流程或部署；均为本项目实施优先级。

### F01 · P0：Run → 战斗丢失永久状态

实测构造十张已升级卡、最大生命 120、当前生命 105、进阶 8 的 Run，再进入战斗，得到：

```text
Run 升级卡数 = 10       战斗升级卡数 = 0
Run 最大生命 = 120      战斗最大生命 = 80
战斗当前生命 = 105      出现当前生命超过最大生命
Run 进阶 = 8            战斗进阶 = 0
```

原因是 `_enter_node()` 仅传入卡牌 ID，`start_combat()` 重建默认未升级实例、固定最大生命；调用侧没有传入 `ascension`。战斗结束主要回写 HP，永久改牌、药水、遗物持久计数等也缺少完整的生命周期契约。

模拟器依据：[run.py:517](D:/桌面/尖塔模型/sts2_sim/run.py:517)、[core.py:1232](D:/桌面/尖塔模型/sts2_sim/core.py:1232)、[run.py:704](D:/桌面/尖塔模型/sts2_sim/run.py:704)。源码依据：[Player.PopulateCombatState:806](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Entities.Players/Player.cs:806) 会克隆实际卡牌，并保留 `DeckVersion` 关联。

处理方向：建立持久玩家状态与战斗实例之间的显式映射和双向结算契约；升级、附魔、最大生命、角色资源、药水、永久改牌、遗物计数都必须逐字段定义生命周期。

### F02 · P0：角色参数没有决定完整初始状态

加载真实内容后，实测 `RunEnv(character="silent")` 仍以 HP 80、铁甲战士的 `bash/defend_ironclad/strike_ironclad` 牌组及空遗物列表开始。参数目前主要影响奖励池等部分路径。

模拟器依据：[RunEnv.reset:441](D:/桌面/尖塔模型/sts2_sim/run.py:441)。源码依据：[Player.CreateForNewRun:305](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Entities.Players/Player.cs:305)、[Silent.StartingHp:34](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Characters/Silent.cs:34)：角色初始 HP 为 70，并由角色定义构造玩家。

处理方向：角色初始化统一读取已冻结的角色定义；单角色阶段也必须正确获得初始遗物及资源。

### F03 · P0：训练内容门禁没有落到采样器

实测加载真实内容后，`draft_pool()` 返回 418 张卡，其中 **223 张 `effects_incomplete=True`**。函数只筛选稀有度和是否存在效果，未筛选残缺标记。`random_deck()` 又会混合不同角色的起始牌组和跨角色加牌。这种随机课程不能被当作自然爬塔分布。

此外，`train_combat.py` 没有显式内容加载参数或初始化调用；`_autoload_from_env()` 在当前代码中仅定义，没有发现调用点。因此默认启动训练仍使用内置占位内容。

依据：[ppo.py:41](D:/桌面/尖塔模型/sts2_rl/ppo.py:41)、[ppo.py:58](D:/桌面/尖塔模型/sts2_rl/ppo.py:58)、[训练入口](D:/桌面/尖塔模型/train_combat.py:24)、[content.py:1989](D:/桌面/尖塔模型/sts2_sim/content.py:1989)。

处理方向：启动时显式加载内容和训练配置，执行依赖闭包门禁，再构建词表与网络；日志打印并保存实际内容哈希。训练配置缺失或内容不可用时终止，不能自动切回 builtin。

### F04 · P0：模型看不到已经实现的重要机制

战斗 `Observation` 没有遗物、药水、充能球、星星等字段；特征编码只保留力量、易伤、虚弱。实测只给公开观察增加 9 层中毒，最终网络输入完全不变。遗物和药水 token 当前只是空占位。牌堆编码还忽略升级标记。

这会产生不必要的信息缺失：环境按中毒、遗物、球等机制结算，策略却没有条件选择不同动作。当前网络没有 GRU/LSTM，历史也没有普遍编码。

依据：[Observation:82](D:/桌面/尖塔模型/sts2_sim/observe.py:82)、[featurize.py:119](D:/桌面/尖塔模型/sts2_sim/featurize.py:119)、[牌堆编码:273](D:/桌面/尖塔模型/sts2_sim/featurize.py:273)、[PolicyValueNet:110](D:/桌面/尖塔模型/sts2_rl/nets.py:110)。

处理方向：先补齐公开状态和候选动作表示，再增加记忆网络。网络变大不能弥补根本未输入的信息。

### F05 · P0：怪物状态机框架存在，但条件输入不完整

`_choose_intent()` 构造 `MonsterContext` 时未传怪物专属 flags/counters；访问器将缺失值默认为 False/0，槽位也被简化为 first/second。

实测单独生成 Fabricator，初始意图为 `disintegrate`。源码 `CanFabricate` 的条件是存活队友少于 4，因此该场景应进入召唤相关随机分支。状态机解释器可执行，不能证明接入上下文正确。

模拟器依据：[core.py:970](D:/桌面/尖塔模型/sts2_sim/core.py:970)、[MonsterContext:72](D:/桌面/尖塔模型/sts2_sim/monster_ai.py:72)。源码依据：[Fabricator.cs:51](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Monsters/Fabricator.cs:51)、[原始状态机](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.MonsterMoves.MonsterMoveStateMachine/MonsterMoveStateMachine.cs:32)。

处理方向：把遭遇槽位、专属字段及转移时副作用作为怪物实例状态；必需字段缺失时报错。必须分别验证“转移条件”和“招式实际效果”。

### F06 · P0：已有伤害管线仍存在可复现的时序差异

实测基础攻击 10、目标易伤、目标 3 层 Tainted：当前 `compute_damage()` 返回 **18**。源码先处理所有加法再乘法，应为 `int((10 + 3) × 1.5) = 19`。当前 Tainted 加成被放到乘法之后，说明“逐句一致”的文档结论不能作为验证依据。

依据：[core.py:410](D:/桌面/尖塔模型/sts2_sim/core.py:410)、[TaintedPower.cs:19](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/TaintedPower.cs:19)、[Hook.ModifyDamageInternal:2520](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Hooks/Hook.cs:2520)。

此外，卡牌效果遇选择而挂起后，`step()` 仍立即调用 `on_card_played()`；完整续跑后的 AfterCardPlayed 时机需要独立对照。源码还分两轮执行普通和 Late 钩子，不能因为去掉动画就合并顺序。依据：[step:1313](D:/桌面/尖塔模型/sts2_sim/core.py:1313)、[Hook.AfterCardPlayed:278](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Hooks/Hook.cs:278)。后者属于静态识别的待对拍风险，本次未逐卡复现。

### F07 · P1：随机流名称相同，不代表同种子轨迹一致

当前采用 SHA-256 派生加 Python `random.Random`；源码 `Rng` 使用按名称哈希混入的种子和 `MegaRandom`，后者是 Xoshiro256**。Run 进入每场战斗又派生新 seed 并新建 RNG；源码玩家的战斗牌堆使用 Run 的 Shuffle 流。

依据：[rng.py:78](D:/桌面/尖塔模型/sts2_sim/rng.py:78)、[Rng.cs:54](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Random/Rng.cs:54)、[MegaRandom.cs](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Random/MegaRandom.cs:52)、[Player.cs:806](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Entities.Players/Player.cs:806)。

处理方向：区分“分布相符的随机训练”和“同种子逐步回放”。训练未必要求复制真机每一个随机比特；SL 重放与严格对拍则要求相应状态和消费顺序吻合。独立随机流本身不会自动造成有用相关性，不能仅凭流名推断或宣称一致。

### F08 · P1：地图、遭遇、奖励与幕流程仍是近似整局

当前地图按固定权重、邻列连接生成，缺少原始地图的路径约束、类型数量与剪枝；问号被简化为事件。`RunEnv` 在第一幕 Boss 胜利后直接终局。遭遇按类型独立抽取，并为所有地图节点预生成奖励和商店。

源码地图有专用 `act_*_map` RNG 和父子节点等约束；`ActModel.GenerateRooms()` 生成弱怪/普通怪/精英等序列并处理重复标签；卡牌稀有度还有会变化的偏移值。`UpFront` 的注释不能被解释为“每个地图坐标的所有奖励都在开局固定”。

依据：[mapgen.py:66](D:/桌面/尖塔模型/sts2_sim/mapgen.py:66)、[run.py:488](D:/桌面/尖塔模型/sts2_sim/run.py:488)、[run.py:704](D:/桌面/尖塔模型/sts2_sim/run.py:704)、[StandardActMap.cs:86](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Map/StandardActMap.cs:86)、[ActModel.cs:331](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Models/ActModel.cs:331)、[CardRarityOdds.cs:75](D:/桌面/尖塔模型/data/decompiled/sts2/MegaCrit.Sts2.Core.Odds/CardRarityOdds.cs:75)。

处理方向：按照“公开地图图结构 + 幕级房间序列 + 运行时奖励生成 + 历史概率状态”重构 Run。章节数、Boss 与最终胜利条件由冻结版本的规则定义，不硬编码为当前文档中的某个数字。

### F09 · P1：选择界面和动作空间尚未完整接通

`PendingSelection.candidates()` 支持手牌、弃牌和抽牌堆，但观测仅给选牌用途和剩余数量，没有候选实体列表；特征编码把 `select_card` 索引解释成手牌索引。来自其它牌堆的选择因此无法正确表示。对于抽牌堆，内部列表顺序也不能直接作为玩家选择的排列。

`use_potion()` 是可调用效果函数，但合法动作和策略动作词表没有药水动作。地图观测含节点位置与当前 reachable，**没有完整 edges**，不足以完整规划后续路线。手牌/敌人使用切片，超过固定容量时可能截断观察。

依据：[PendingSelection:216](D:/桌面/尖塔模型/sts2_sim/core.py:216)、[legal_actions:348](D:/桌面/尖塔模型/sts2_sim/core.py:348)、[featurize.py:39](D:/桌面/尖塔模型/sts2_sim/featurize.py:39)、[RunObservation:218](D:/桌面/尖塔模型/sts2_sim/observe.py:218)。

处理方向：统一可见候选列表和实体句柄；药水、选牌、跳过、确认、重开都走同一决策接口。容量溢出显式报错或动态扩容，不静默截断。

### F10 · P1：SL 需要真实可执行的协议与历史

当前战斗 SL 可以直接恢复历次最佳终局快照；Run 层则是 `restart_node()` 恢复节点入口，缺少与战斗相同的统一元决策流程。历史只记录回合开始手牌，没有完整记录回合中抽牌、行动、随机目标等公开事件。

依据：[env.py:257](D:/桌面/尖塔模型/sts2_sim/env.py:257)、[env.py:312](D:/桌面/尖塔模型/sts2_sim/env.py:312)、[run.py:864](D:/桌面/尖塔模型/sts2_sim/run.py:864)。

处理方向：统一重开次数含义、可重开时机、恢复点、死亡/胜利后能力及最终提交。使用公开动作—观察日志保存试次知识；重放最好一次时验证每步公开反馈。不同动作会改变洗牌和随机消费，上一试次的观察不能被当成所有分支共同的未来牌序。

### F11 · P1：统计工具和文档会高估可信程度

`architecture_audit.py` 在数量差不超过 30 时直接打印“数量对齐”；“忠实翻译”“307 行”“109 只怪”等部分结论是写死的打印文本，非行为验证。`content_status.py` 的“可训练”统计按内容标记分桶，而实际采样器没有执行相同过滤。

依据：[architecture_audit.py:73](D:/桌面/尖塔模型/tools/architecture_audit.py:73)、[content_status.py](D:/桌面/尖塔模型/tools/content_status.py:100)。

处理方向：报告区分存在、解析、执行、依赖闭包、源码用例、真机差分验证六种状态；“测试通过”和“模拟正确”分开。禁止通过固定描述打印“已一致”。

### F12 · P1：训练尚未覆盖正式目标

现有 PPO 面向战斗，环境池是同步 Python 循环；没有完整 Run 学习器和序列记忆训练。两维 value 中第一维用回报回归训练，不能直接解释为已校准胜率。势函数塑形实现是 `Phi(next)-Phi(now)`，只与当前 `gamma=1` 配置匹配；若允许改变 gamma，塑形公式也必须使用同一个 gamma。

模型 checkpoint 仅保存权重与配置，缺少内容、词表、观察协议、SL 协议和源码版本指纹。内容变化后同名 embedding 索引可能指向不同卡牌。

依据：[ppo.py:124](D:/桌面/尖塔模型/sts2_rl/ppo.py:124)、[ppo.py:167](D:/桌面/尖塔模型/sts2_rl/ppo.py:167)、[训练保存入口](D:/桌面/尖塔模型/train_combat.py:70)。

## 4. 可复用的基础

| 基础 | 保留理由 | 需要补的边界 |
|---|---|---|
| `observe.py` 单一投影与牌堆 bag | 已有清晰的信息隔离方向 | 保留全部公开实例属性；补候选、地图边、资源和历史 |
| `monster_ai.py` | 已能解释多种转移结构 | 完整运行时上下文、遭遇槽位、专属状态与副作用 |

env = RunEnv(seed=7, ascension=8, attempt_budget=0)
