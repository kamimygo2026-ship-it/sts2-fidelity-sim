# 04 · 训练方法

## 4.0 为什么不能一步到位

| 困难 | 具体表现 |
|---|---|
| **稀疏奖励** | 一局 50+ 房间、200–500 次决策，最后只有 1 bit（通关/死亡） |
| **信用分配跨度大** | 第 3 层拿的一张牌决定第 40 层的生死，中间隔了 10³ 步 |
| **动作不可逆** | 拿错牌、走错路，无法回头 |
| **对手是脚本** | 没有自博弈对手，不能靠"对抗更强对手"来提升——**策略提升的来源只有自己的探索与数据** |
| **泛化要求高** | 每局牌组、遗物、遭遇都不同，不能背答案 |

→ 结论：**分层 + 课程 + 模仿/塑形**，四者缺一不可。下面六个阶段按顺序做，每个阶段都有明确验收标准。

## 4.1 阶段 0：先写一个规则 bot

**这是整个项目性价比最高的一步，不要跳过。**

一个手写启发式 bot：

- **战斗**：能斩杀就斩杀；否则按"每点能量的伤害/格挡效率"排序出牌；面对高额攻击意图优先堆格挡
- **选牌**：给每张卡打一个静态分（可用社区 tier list 或手调），选最高分
- **路线**：血量健康多打精英，血量低优先营火

**它的四个作用：**

1. **模拟器的压力测试**——一个能稳定打到 Act 2 的 bot 说明机制大致没写错（如果它总是莫名其妙暴毙，是模拟器有 bug）
2. **行为克隆的数据源**（没有人类数据时的兜底）
3. **RL 的回归基线**——"RL 必须显著打败它"，否则整个项目没有意义
4. **探索的起点**——用 bot 的策略初始化 PPO 的 actor，比从随机策略开始快得多

> 反直觉但重要：**先花一周写 bot，能省下后面一个月的调试。** 没有基线的 RL 实验无法判断"是模型不行还是环境有 bug"。

## 4.2 阶段 1：行为克隆冷启动

**目的：让策略不至于完全随机地探索。** 纯随机策略在 StS 里几乎不可能通关，稀疏奖励下 PPO 永远等不到第一个正样本。

### 数据源优先级

**关键事实：人类数据只覆盖 Run 层，不覆盖战斗层。** 侦察结论（`docs/07` §7.6）：社区 run 日志包含卡牌三选一（每个选项带 `was_picked`）、营火选择、药水使用、商店选择，**但不含战斗内的逐回合出牌序列**（只有每房间的 `turns_taken`）。所以两层的 BC 策略必须分开设计：

| 层 | 人类数据 | 冷启动方案 |
|---|---|---|
| **Run 层**（选牌/地图/商店/营火/事件） | ✅ 有（社区 run 日志，量大） | **直接做行为克隆** —— 这正是"像人一样选牌"最直接的实现 |
| **战斗层**（出牌/目标/药水） | ❌ 无 | 规则 bot 自博弈 → 束搜索 + 价值网络（§4.3） |

> 这是一个好消息而不是坏消息：**"像人一样选择卡牌"这个需求恰好落在有真人类数据的层上**。而战斗层本来就更适合"搜索 + 评估"的形态（见 §4.3），它不缺数据也没关系。
>
> 注意 `has_replay` 字段存在但接口未返回回放体——**战斗出牌序列可能藏在里面**，M0 阶段值得花半天把它挖出来。如果挖到了，战斗层的 BC 就从"可选"变成"优先"。

### 训练细节

- 损失：各动作阶段分别算交叉熵（`kind` / `card` / `target`），加权求和
- 加**熵正则**（系数 0.01）：防止学成确定性策略，否则后续 RL 没有探索空间
- 只对**合法动作**算损失（用 mask）
- 数据增强：对同一局面，用不同隐藏 RNG 采样（determinization）→ 让模型见过"同一局面下多种未来"。**这同时也是反泄漏测试的自然副产品**

### 验收标准

1. 在 held-out 决策上 top-1 一致率超过阈值（战斗出牌 >70%，选牌 >60%）
2. **闭环测试**：让模型自己玩 100 局，平均到达楼层显著超过随机策略
3. 不要求超过 bot——BC 的天花板就是数据质量

## 4.3 阶段 2：战斗层 RL（PPO，最重要的阶段）

**这是全项目投入产出比最高的一段。** 战斗层信号密集（每场战斗几百步内就有胜负与掉血），可以独立训练，而且训好之后它本身就是 Run 层的评估器（§4.4）。

### 环境设置

| 项 | 设置 | 理由 |
|---|---|---|
| 牌组 | **随机采样**（从合理牌组池中抽） | 固定牌组会过拟合，学不出通用战斗技巧 |
| 遭遇 | 随机（按 Act 权重） | 同上 |
| 起始 HP | 随机（80%–100%） | 模拟"带伤进战斗" |
| 遗物/药水 | 随机子集 | 学会用遗物与药水 |
| 并行度 | 1024–4096 场战斗 | 提高吞吐、降低方差 |
| rollout 长度 | 一场战斗（≤200 步） | 天然 episode 边界 |

### PPO 超参起点

```
γ = 1.0                  # 战斗内不打折，胜负就是终局
λ (GAE) = 0.95
clip = 0.2
lr = 3e-4 (cosine 衰减到 3e-5)
minibatch = 4096
epochs = 4
entropy_coef = 0.01 → 0.001（线性衰减）
value_coef = 0.5
max_grad_norm = 1.0
```

**γ = 1.0 是关键选择**：战斗是一个有限时域的终局问题，"30 回合后赢"和"3 回合后赢"对胜负的价值一样（虽然对剩血的价值不同——这正是多任务价值头要捕捉的）。用 γ<1 会让模型偏向速胜而牺牲安全。

### 奖励设计

```
终局:  胜 = +1,  负 = -1

势函数塑形 (potential-based):
  Φ(s) = player_hp_ratio − Σ enemies_hp_ratio / n_enemies
  r_t += γ·Φ(s_{t+1}) − Φ(s_t)

微惩罚（可选，谨慎）:
  每回合 −0.001        # 防拖延
  非法动作不存在        # 由 mask 保证
```

**势函数塑形（potential-based shaping）的理论保证**：形如 `r' = r + γΦ(s') − Φ(s)` 的塑形**不改变最优策略**。这直接解决了"加了塑形会不会带偏"的顾虑——可以放心用。

**明确不要做的事**（都是典型 reward hacking 来源）：

| 反模式 | 会学到什么 |
|---|---|
| 奖励"造成的总伤害" | 不打格挡、送死换输出 |
| 奖励"剩余能量为 0" | 无意义地乱出牌 |
| 直接奖励"剩余 HP"（非势函数形式） | 拖回合、不敢进攻 |
| 惩罚"回合数"过重 | 冒险速杀，死亡率上升 |

### 课程学习（按顺序解锁，每级有验收）

| 级 | 内容 | 学会什么 |
|---|---|---|
| 1 | 单一弱怪 + 固定牌组 | 伤害/格挡的基础交换 |
| 2 | 随机牌组 + 单怪 | 泛化到不同牌组 |
| 3 | 双怪/三怪 + AoE | 目标选择与 AoE 权衡 |
| 4 | 精英 + Boss | 长战斗、爆发窗口、buff 管理 |
| 5 | **连续多场战斗**（Act 1 全流程） | **"HP 是跨战斗的资源"**——学会省血、学会为下一场留牌 |
| 6 | 难度递增（Ascension） | 鲁棒性 |

**第 5 级是最关键的一跃**：单场战斗里"用 15 血换速胜"是合理的，但在连续战斗中这是灾难。这个长程概念只能通过连续战斗学会。如果只做单场战斗训练，得到的 agent 在完整 run 里会表现得很差——这是最容易踩的坑。

### 验收标准

1. 固定测试牌组集上，每个遭遇的胜率与平均剩血超过规则 bot
2. **泛化测试**：held-out 牌组（训练中从未出现的组合）上仍保持优势
3. 行为审查：人工看 20 局，确认没有明显的怪异打法（拖延、乱出牌、自杀式进攻）

## 4.4 阶段 3：Run 层（牌组构建）

### 核心简化：用战斗专家当"牌组评估器"

StS 有一个别的游戏没有的结构性便利：**牌组的好坏可以通过模拟战斗来评估**。

```
f(deck D) → (胜率, 期望剩余 HP)
   实现：用阶段 2 的策略，在 N 个采样遭遇上各跑 M 次，取统计量
```

这就是一个现成的、便宜的牌组强度函数。**不需要训练任何东西就能用。**

### 三种做法（按工程量递增）

**(a) 蒙特卡洛前瞻（先做这个，不需要训练）**

```
卡牌三选一时：
  for 每个候选牌 c:
      把 c 加入牌组，用战斗专家跑 K 次固定基准遭遇
      score(c) = 期望剩余 HP（或胜率）
  选 argmax score
```

- 立刻可用，且**天然符合"不读随机数"**：每次模拟用不同的隐藏状态采样，取平均——这正是 `docs/01` §1.4 的信息集搜索。
- 成本：每次选牌 K×3 场战斗模拟。K=32 时约 100 场战斗，在 50k 步/秒的模拟器上是秒级。**完全可接受。**
- 局限：只评估"短期战斗力"，评估不了"这套牌 20 层后能不能赢 Boss"。

**(b) 蒸馏成 `V_run` 网络**

用 (a) 生成的 `(局面, 候选, 评分)` 数据监督训练 Run 层策略头 + `V_run`。推理时一次前向传播代替几千步模拟。

**(c) 端到端 RL**

直接用完整 run 的回报训练 Run 层。信号最真实，但最稀疏、最慢。留到阶段 4。

> **推荐路径：(a) 拿结果 → (b) 蒸馏加速 → (c) 精调。** 顺序反了会浪费几周。

### 地图选路

用 `V_run`（或采样估计）评估"从某节点出发的通关概率"：

```
V_node = E[ Σ 未来收益 | 从该节点出发 ]
选择 argmax V_node
```

注意：**未来楼层的内容是隐藏信息**，采样时每次重新掷（不同遭遇、不同掉落），取平均——同样符合信息集原则。

## 4.5 阶段 4：全流程联合微调

用阶段 1–3 的权重初始化，端到端 PPO over 完整 run。

| 项 | 设置 |
|---|---|
| lr | 1e-4 → 3e-5（比阶段 2 小一个量级，避免破坏已学好的战斗技巧） |
| 并行 | 每个 worker 跑一个完整 run，多个 run 拼成 batch |
| 序列处理 | **truncated BPTT + stored state**（R2D2 式），不要每步重算 GRU |
| padding | run 长度差异大，注意 mask 掉 padding 步的损失 |
| 奖励 | 通关 +1 / 死亡 −1，或"最大层数 + 分数"作稠密信号 |

**交替更新**：Run 层与战斗层轮流冻结训练。全参数同时更新时，稀薄的 run 信号会污染已训好的战斗层（表现为战斗胜率莫名下降）。

## 4.5b SL 元策略：何时重开（本项目特有）

按 `docs/01` §1.4，SL 训练下策略要回答三个问题，其中"何时重开"是一条**独立的策略头**，必须显式训练——它不会从战斗策略里自动涌现。

### 元决策的形式化

```
在试次 i 结束时，观察 (可见状态, 试次 1..i 的历史, 已用重开次数 j)
决策: 接受 / 重开
约束: j < K
```

### 训练方案（三选一，按工程量）

**(a) 阈值规则（先做这个，零训练成本）**

```
if 战斗已失败: 重开
elif 估计剩余 HP < 阈值(节点类型): 重开
else: 接受
```

用它跑通 SL 管线、拿到 K=1 与 K>1 的胜率对比。**先有这个数字，再谈优化。**

**(b) 用 `V_run` 做一步比较**

```
重开的价值 = E[V_run(重开后的局面)] − V_run(当前局面)
重开 if 这个差 > 成本(算力/次数)
```

好处：不需要额外网络。坏处：`V_run` 本身要先训好，且它是在 NoSL 语义下训的。

**(c) 端到端训练元策略头**

把 meta-episode 当作一个 MDP：状态 =（可见状态, 试次历史），动作 = {接受, 重开}，回报 = 最终通关 + 重开次数惩罚。用 PPO 训练。

### 三个必须注意的坑

| 坑 | 后果 | 规避 |
|---|---|---|
| **元策略学会了"无限重开"** | 算力爆炸，且与人类行为不符 | 环境强制 K 上限；回报里加重开次数惩罚 |
| **元策略学会"重开刷牌序"** | 如果模拟器 restore 重掷 RNG，它会学到真机不存在的策略 | `docs/01` §1.6 测试 2（重开语义测试）必须在 CI 里 |
| **只在 SL 下评估** | 无法判断实力有多少来自重开知识 | **必须同时报告 K=1 胜率**（`docs/01` §1.5） |

### 最有价值的实验

```
K=1（不允许重开） vs K=4 vs K=16 的胜率曲线
```

- 曲线陡峭 → 实力主要来自"逐步观察牌序"，这是**真实的 SL 技能**，人类玩家也是这样玩的
- 曲线平坦 → 重开没有可被利用的信息，说明 agent 没学会用跨试次知识
- **K=1 的绝对胜率** → 衡量"牌理"水平，与 NoSL 训练的结果可直接对比

## 4.6 阶段 5：信息集搜索增强（可选）

按 `docs/01` §1.4 实现 determinization + common random numbers：

```
K = 8–32 个隐藏状态采样
只在关键决策点启用：Boss 战、濒死回合、卡牌三选一
Q(a) = (1/K) Σ_k rollout_return(sample_k, a)
```

**再次强调**：所有候选动作必须共享同一批采样，且一个决策点只采样一次。否则会退化成偷看真实随机数。

替代方案：**一步前瞻**（枚举本回合合法动作，用 `V_combat` 评估后继）。代价 O(动作数) 次前向传播，在 50k 决策/秒的推理速度下完全可行。ForgottenArbiter 在 StS1 上的工作验证了这是本类问题性价比最高的搜索形式。

## 4.7 算力与吞吐预算（单卡 4090 + 16 核的粗略估计）

| 阶段 | 规模 | 墙钟估计 |
|---|---|---|
| 规则 bot 数据生成 | 10⁶ 局决策 | 数小时 |
| 战斗层 PPO | 10⁸ – 10⁹ 环境步 | 1–5 天 |
| Run 层 MC 数据 | 10⁶ 次战斗模拟 | 数小时 |
| Run 层蒸馏 BC | 10⁵ – 10⁶ 样本 | 1 小时 |
| 联合微调 | 10⁷ – 10⁸ 步 | 数天 |

**前提条件**：环境 ≥50k 步/秒、训练 ≥5k 决策/秒。

**如果达不到，先优化模拟器，不要先加大网络。** 环境吞吐是这个项目的第一生产力——它决定了你能做多少次实验。

## 4.8 反 reward hacking 清单

| 作弊行为 | 检测 | 对策 |
|---|---|---|
| 拖延回合刷格挡 | 平均回合数异常升高 | 回合上限 + 势函数塑形（而非直接奖励 HP） |
| 不打怪，反复做无意义操作 | 动作分布监控：`end_turn` 占比、重复动作检测 | 每回合微惩罚 |
| 利用模拟器 bug 无限循环 | 不变量测试 + 步骤上限 | 修 bug；这是模拟器问题不是策略问题 |
| 故意输掉弱战斗避免风险 | 胜率与"战斗跳过率"关联分析 | 终局奖惩对称 |
| **过拟合到训练种子** | 训练 vs 留出种子集的表现差距 | 每 episode 新种子；种子不进观测 |
| 记忆特定牌组 | held-out 牌组上的表现 | 牌组随机化 + 泛化测试 |

**例行人工审计**：每轮训练后抽 100 局看 `render_text()` 输出。这是唯一能发现"统计上正常但打法荒谬"的手段。

## 4.9 常见失败模式速查

| 症状 | 最可能的原因 |
|---|---|
| 胜率长期 0，梯度正常 | 奖励太稀疏 + 没做 BC 冷启动；或 mask 没生效，策略在无效动作上打转。**已有人踩过这个坑**：`docs/07` §7.1 的项目在 100 万步后全局通关率仍是 0% |
| 战斗很强但全局为 0 | 典型的分层缺失 + 扁平观测/动作。同样是 `docs/07` §7.1 的实际结果 |
| 重开次数爆炸 | 元策略没有成本约束（§4.5b） |
| 模拟器里重开有用，真机里没用 | restore 重掷了 RNG，SL 语义被破坏（`docs/01` §1.6 测试 2） |
| 学会只用防御 | 势函数塑形系数过大，或奖励了"剩余 HP" |
| 熵塌缩（策略变成确定性） | entropy 系数太小；及早停掉 entropy 衰减 |
| 训练胜率高，测试低 | 过拟合牌组/种子；检查是否泄漏了种子 |
| 战斗层很好，完整 run 很差 | 没做课程第 5 级（连续战斗），模型不知道 HP 是跨战斗资源 |
| Run 层拿牌水平像随机 | `V_run` 没训好；先用 §4.4(a) 的 MC 前瞻做对照 |
| 换了张卡就崩 | 纯 ID embedding，没有文本先验；加 `docs/03` §3.3 的文本 embedding |
| 真机表现远差于模拟器 | sim2real gap；见 `docs/05` 风险表第一条 |
