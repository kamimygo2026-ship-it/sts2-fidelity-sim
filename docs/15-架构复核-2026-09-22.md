## 2. 按影响排序的发现

### R1【P1】自动出牌没有遵守统一的暂停、完成和重复结算协议

代码位置：[core.autoplay_card / _autoplay_sly / _run_card_plays / _resolve_selection](../sts2_sim/core.py)。

手动打牌通过 `_run_card_plays` 检查 `_apply_effects` 是否挂起。`autoplay_card` 则忽略其返回值，继续触发 `AfterAttack`、`AfterCardPlayed` 并把牌移出 play_area。`_autoplay_sly` 同样没有等待选择完成，且与通用自动打牌另有一套结算路径。

**已复现：**让 Headbutt 自动打出，弃牌堆有一张防御，玩家有 1 层 Afterimage。选牌尚未完成时，玩家已经获得 1 格挡，Headbutt 已进入弃牌堆且出牌区为空；它甚至进入了自身选牌候选。继续完成一次选择后，所有牌堆中同一 Headbutt uid 出现两次。

这不是单纯日志顺序问题：候选集合和牌实例数量已经改变。Headbutt、Afterimage 及能触发自动出牌的 Stampede/Mayhem 均在当前准入范围内。

**第二个反例：**1 层 OneTwoPunch 下，基础打击手动打出造成 12 伤害，自动打出只造成 6 伤害。通用自动出牌没有经过 `GeneratePlayCount` 对应的规则。源码 [CardModel.OnPlayWrapper](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models/CardModel.cs:1858) 对自动与手动均计算 playCount；[OneTwoPunchPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/OneTwoPunchPower.cs) 也没有排除自动打出。[Headbutt](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Cards/Headbutt.cs) 和 [AfterimagePower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/AfterimagePower.cs) 可直接核对选择和完成时机。

**架构判断：**“集中一个 AfterCardPlayed 函数”仍不足以保证只有正确时机能调用它。需要统一 `play_card(context)` 执行流程，手动/自动/Sly 只提供费用、目标和自动模式等差异；每次出牌有自己的资源、重复次数、局部状态和完成标志。执行帧是当前正确性前置条件，不能移到另一个批次后将原工单标成完成。

验收：手动/自动/Sly 的普通、重复、选择、嵌套选择分别对拍；暂停期间不完成；每个 uid 恰属于一个牌区；一个 playIndex 恰好完成一次；父帧资源不被子出牌覆盖。

### R2【P1】训练环境只传递了角色牌组，丢掉角色上下文

代码位置：[CombatPool._spawn / make_env](../sts2_rl/ppo.py)、[SpireEnv.__init__ / reset](../sts2_sim/env.py)、[core.start_combat](../sts2_sim/core.py)。

RunEnv 已能把 character 传入战斗；训练所用 SpireEnv 没有相应参数，只把 deck、encounter、seed、player_hp 传给 start_combat。因此两个环境创建出来的 CombatState 含义不一致。

**已复现：**`CombatPool(n_envs=1, base_seed=1, character="defect")` 的配置角色是 defect，但内部 `CombatState.character == "ironclad"`，最大生命 80、遗物为空。调用实际生成能力所使用的生成入口，得到 `unmovable / cruelty / feel_no_pain`，三张都不属于缺陷角色池。

生命和遗物可以作为明确的训练课程变量；**不能连生成规则的角色也意外改变**。源码 [CreativeAiPower](../data/decompiled/sts2/MegaCrit.Sts2.Core.Models.Powers/CreativeAiPower.cs) 从玩家角色卡池取牌。

**架构修正：**RunEnv 与 SpireEnv 共用显式 CombatInit/EncounterContext，至少传递角色、进阶、房间、资源、遗物/药水和所属随机流。课程覆盖值另有字段和 manifest 记录。禁止默认 ironclad 静默补全已经声明了其它角色的训练。

验收：从同一个公开战斗配置经 Run、训练和回放三条入口初始化，角色及规则相关字段一致；五个角色分别做生成池检查。

### R3【P1】运行时生成依赖绕过内容闭包；旧的被动查询漏检也仍存在

代码位置：[eligibility.generated_cards / closure_gaps](../sts2_sim/eligibility.py)、[powers.generate_cards_to_hand](../sts2_sim/powers.py)、[run.draw_card_reward](../sts2_sim/run.py)。

闭包目前主要跟踪效果表里的显式 add_card 和固定卡引用。CreativeAi/HelloWorld 等通过已注册能力在运行时访问卡池，卡 → 能力 → 候选池这条依赖没有进入准入图。

**已复现：**creative_ai 被准入；使用 defect 战斗状态、`combat_card_generation` 所属 RngSet 测试种子 8，生成一张能力牌得到 `biased_cognition`，而该卡被门禁以 effects_incomplete / unimplemented_power 拒绝。这里直接测试生成函数，没有伪称运行了完整 CreativeAi 战斗。

另外重新确认两条旧问题：`draw_card_reward(RngSet(0))` 仍会生成不合格的 demonic_shield；Normality 仍被准入，持有它打完三张防御后第四张仍可打。

**架构修正：**准入单位必须覆盖内容所有行为及完整生成依赖，不只是 apply_power 的名字已注册。把能力/遗物/事件的候选池和选择用途纳入依赖图；所有入口统一使用场景 profile。受限课程预先缩池并标注分布变化，完整范围模式遇到缺失内容应记录 unsupported，不能生成后静默删效果或重抽。

验收：奖励、商店、转化、药水、能力造牌、召唤逐入口证明不会产生范围外对象；被动限制/查询缺失也能阻止准入。

### R4【P1】公开观察与实际规则不一致，模型输入又进一步丢信息

代码位置：[observe.observe](../sts2_sim/observe.py)、[featurize.encode_observation](../sts2_sim/featurize.py)、[core.play_cost / legal_actions](../sts2_sim/core.py)。

**已复现：**腐败生效、能量为 0、手中有防御时，实际费用为 0，合法动作包含出牌；观察却给出 `cost=1, playable=False`。观察使用 card.cost() 等静态计算，未使用实际费用/合法性查询。

保持其余观察及合法动作不变，只增加 9 层中毒，所有编码数组完全相同；球槽数增加 2 也完全相同。当前能力已经扩到 197 个，但张量化仍只直接编码 strength/vulnerable/weak 这三个能力量。

**架构修正：**可见费用、可打性、动态数值由共用查询产生，然后统一投影；编码增加能力实体、公开计数、球槽、实例修正等。模型无需获得 RNG 或隐藏顺序，但必须看见游戏公开给玩家的规则相关区别。

验收同时检查正反两边：公开状态变化应改变相应编码；只改变隐藏状态而公开结果不变时，编码与公开候选必须不变。正确 action mask 不能补救自相矛盾的观察字段。

### R5【P1】Run 的 RNG 有两个所有者，节点恢复后引用分裂

代码位置：[RunEnv.reset / _begin_act / restart_node](../sts2_sim/run.py)。

reset 令 `self._rng` 与 `state.hidden.rng` 指向同一对象；restart_node 只 deepcopy 恢复 `_state`，没有恢复 `_rng`。后续 `_begin_act` 用旧 `_rng` 预生成内容，其它逻辑使用已恢复的 `state.hidden.rng`。

**已复现：**重开前二者 `is` 为 True，重开后为 False。seed=4 下，在节点快照后生成第二幕、恢复同一快照、再生成第二幕，28 个节点的遭遇/卡牌奖励/金币组合与第一次不同。该探针直接调用幕交接以隔离恢复问题，没有声称实际通关到第二幕。

**架构修正：**RunState 内的 Hidden 是持久随机状态的唯一所有者，环境外壳不保留另一份可推进引用；所有跨幕概率、队列和随机流都在同一恢复闭包中。只把两个引用重新绑起来可以止损，但还应检查其它外壳缓存是否保存状态对象。

验收：任意声明的节点恢复点，重复相同动作/跨幕交接应得到相同环境结果；不同尝试只保留合法观察记忆，不能留下旧环境随机进度。

## 4. 架构应保留什么、先改什么

继续保留现有语言和模块主干。core/powers 变大不是单独判定架构错误的理由；真正的问题是同一规则有多个执行入口、状态上下文靠默认值补全、恢复对象有外部别名、准入与生成脱节。

推荐下一阶段顺序：

1. **先让课程边界真实有效。** 对 R1/R3 尚未支持的组合明确阻止准入，同时修 R2 的角色传递与 R4 的观察/费用查询。不要仅提高“支持牌数”。
2. **统一出牌执行。** 手动/自动/Sly 共用执行器和 PlayContext；在此基础上让帧保存选择、重复结算和嵌套资源，取代单 pending 的父子覆盖风险。
3. **统一状态所有权。** 修 Run RNG 恢复引用，扩充 Run/SpireEnv 初始化契约；永久状态、战斗状态、执行上下文、合法观察记忆各有生命周期。
4. **扩充依赖图与验证。** 把运行时生成、查询、记账和事件返回纳入闭包；新机制至少覆盖一次与自动出牌、选择或重开的交互。
5. **随后继续内容填充及序列训练。** GRU、Run 策略、搜索和真机适配的总体规划仍成立；先完成上面的环境契约再扩大训练规模。RNG 位级一致和源码幕队列也仍未完成。

“修架构”应落实为这些具体契约，不是先拆分所有大文件或建设全能 C# 转译器。每次提取以一个已经失败的组合为验收，不改变无关规则。

## 5. 可重现的关键探针

以下代码在项目根目录执行，只修改内存中的测试局面；`raw_state` 和 Hidden 访问仅用于审计，禁止进入策略路径。

from dataclasses import replace
import numpy as np
from sts2_sim.featurize import configure_content, encode_observation
configure_content("data/content/repo")
from sts2_sim import core as c, powers, eligibility as g
from sts2_sim.observe import observe
from sts2_sim.run import RunEnv, draw_card_reward
from sts2_sim.rng import RngSet
from sts2_rl.ppo import CombatPool

def state(cards):
    s = c.start_combat(cards, ["axebot"], seed=1)
    s.enemies[0].hp = s.enemies[0].max_hp = 1000
    s.enemies[0].powers.clear()
    return s

# R1：自动出牌的挂起和实例唯一性。
s = state(["headbutt", "defend_ironclad"])
card = next(x for x in s.hand if x.cid == "headbutt")
s.hand = [card]
s.discard = [c.CardInstance("defend_ironclad")]
s.player.powers["afterimage"] = 1
c.autoplay_card(s, card, [])
print("pending/block/play_area", s.pending is not None, s.player.block, len(s.play_area))
c.step(s, c.legal_actions(s)[0])
print("same uid count", sum(x.uid == card.uid for x in s.all_piles()))
# 当前：True / 1 / 0；同 uid 计数 2。

for auto in (False, True):
    s = state(["strike_ironclad"])
    s.player.powers["one_two_punch"] = 1
    hp = s.enemies[0].hp
    if auto:
        c.autoplay_card(s, s.hand[0], [])
    else:
        c.step(s, c.Action("play_card", 0, 0))
    print("auto/damage", auto, hp - s.enemies[0].hp)
# 当前：False / 12；True / 6。

# R2：实际训练入口的上下文。
pool = CombatPool(n_envs=1, base_seed=1, character="defect")
s = pool.envs[0].raw_state
print("requested/actual", pool.character, s.character)
# 当前：defect / ironclad。

# R3：生成依赖不在闭包内。
s = c.start_combat(["defend_defect"], ["axebot"], seed=1, character="defect")
s.hidden.rng = RngSet(8)
made = powers.generate_cards_to_hand(s, 1, [], card_type="power")
print("creative_ai admitted", g.card_admission("creative_ai").admitted)
print("generated/admitted", made, [g.card_admission(x).admitted for x in made])
# 当前：True；['biased_cognition'] / [False]。
reward = draw_card_reward(RngSet(0))
print("reward rejected", [x for x in reward if not g.card_admission(x).admitted])
# 当前：['demonic_shield']。

# R4：实际费用与观察矛盾；公开特征消失。
s = state(["defend_ironclad"])
s.player.powers["corruption"] = 1
s.energy = 0
o = observe(s)
actions = c.legal_actions(s)
print("actual/observed/legal", c.play_cost(s, s.hand[0]), o.hand[0], actions)
base = encode_observation(o, actions)
for name, changed in {
    "poison": replace(o, player_powers=o.player_powers + (("poison", 9),)),
    "orb_slots": replace(o, orb_slots=o.orb_slots + 2),
}.items():
    encoded = encode_observation(changed, actions)
    print(name, [k for k in base if not np.array_equal(base[k], encoded[k])])
# 当前：实际费用 0；观察 cost=1/playable=False；合法动作含出牌；两个字段差异均 []。

# R5：隔离节点恢复与跨幕内容生成，未模拟真实打赢整幕。
env = RunEnv(seed=4, attempt_budget=3)
env.reset()
env.step(next(a for a in env._step_view().legal if a.kind == "choose_node"))
def contents():
    return {k: (v.encounter, v.card_reward, v.gold)
            for k, v in env.raw_state.hidden.node_contents.items()}
env._begin_act(2)
first = contents()
env.restart_node()
print("rng same object", env._rng is env.raw_state.hidden.rng)
env._begin_act(2)
second = contents()
print("different nodes", sum(first.get(k) != second.get(k) for k in first))
# 当前：False；28。
