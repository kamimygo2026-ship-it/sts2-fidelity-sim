# 05 · 评估、风险与路线图

## 5.1 评估指标

### 主指标

| 指标 | 定义 | 用途 |
|---|---|---|
| **通关率** | 完整 run 的通关比例，按难度分层 | 最终目标 |
| 平均到达楼层 | 死亡/通关时的层数 | 比通关率更细的刻度（通关率低时有区分度） |
| Boss 击杀率 | 各 Act Boss 的击杀比例 | 定位瓶颈在哪一层 |
| 平均剩余 HP | 战斗/整局结束时的 HP | 策略质量（"惨胜"与"完胜"的区别） |
| 平均回合数 | 每场战斗 | 异常检测（飙升 = 拖延） |

### 诊断指标

| 指标 | 定义 | 诊断什么 |
|---|---|---|
| 决策一致率 | 与人类/bot 在同一局面下的 top-1 一致率 | 像不像人 |
| 泛化差距 | 训练牌组 vs held-out 牌组的胜率差 | 过拟合 |
| 种子差距 | 训练种子 vs 留出种子的胜率差 | 种子记忆（作弊） |
| **sim2real 一致率** | 同一局面下，模拟器 agent 与真机 agent 的动作一致率 | 模拟器保真度 |
| 单场战斗胜率 | 隔离战斗层的能力 | 分层定位问题 |

### 评估纪律

- **固定评估种子集**，与训练种子集不相交，且**永不更换**（否则指标不可比）
- 每组评估 ≥500 局（通关率低时方差极大，几十局的结论没有意义）
- 每次实验记录：代码版本、内容表版本、种子集、超参、指标 → 建立实验台账

## 5.2 CI 门禁（不通过不许合入）

| 类别 | 测试 | 来源 |
|---|---|---|
| **反作弊** | 投影不变性（对**未揭示**变量）、**重开语义测试**、种子不可见、策略纯函数性、影子对局、归因测试、buffer schema 审计 | `docs/01` §1.6 |
| **数值正确性** | 单卡测试、单怪测试、真机回放对拍 | `docs/02` §2.5 |
| **健壮性** | 10⁶ 步自博弈不变量（HP/能量/牌数守恒、无死循环） | `docs/02` §2.5 |
| **接口一致性** | Rust 动作枚举 ↔ Python 动作枚举逐项对齐 | `docs/03` §3.5 |
| **性能回归** | 环境吞吐不得低于基线的 90% | `docs/02` §2.6 |

**建议**：反作弊测试与数值对拍测试**必须在每次 PR 上跑**。这两个是项目的科学诚信基础，一旦被绕过，所有实验结果都不可信，而且很难事后发现。

## 5.3 风险表

| # | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| 1 | **模拟器与真机数值不一致** | 致命——训练的是另一个游戏 | 高 | 真机回放对拍；只纳入已验证内容；domain randomization；最后真机微调 |
| 2 | **稀疏奖励导致学不动** | 高——可能几周无进展 | 高 | 分层（战斗层先训）；规则 bot 冷启动；势函数塑形；课程学习 |
| 3 | **社区数据不全/过时** | 中——机制缺失或错误 | 高 | 版本锁定；覆盖率报告；缺的部分手写并标 `verified: false` |
| 4 | **游戏版本漂移**（EA 每周更新） | 中——数据表失效 | 高 | 数据驱动内容（只改数据不改代码）；版本号绑定；文本 embedding 提升新卡泛化 |
| 5 | 算力不足 | 中——实验周期拉长 | 中 | 先优化环境吞吐；缩小模型；单角色单 Act 先跑通 |
| 6 | reward hacking | 中——指标好看但打法荒谬 | 中 | 势函数塑形；回合上限；例行人工审计 |
| 7 | 信息泄漏（无意中） | 高——结论不可信 | 中 | 四层防护 + CI 门禁（`docs/01`） |
| 8 | 无人类数据 | 中——BC 质量受限 | 中 | 规则 bot 兜底；StS1 迁移；MC 前瞻代替 BC |
| 9 | 许可证/分发问题 | 中——不能开源 | 中 | 不打包游戏资源；数据表按公开来源重建；核实各依赖许可（见待确认清单） |
| 10 | 多人联机误用 | 低——封号/破坏他人体验 | 低 | **明确只做单机**，不加联机支持 |
| 11 | **复用引擎保真度不足** | 高——白费 M0–M1 的力气 | 中 | 先做对拍打分（`docs/02` §2.1）；不达标就退回自建 |
| 12 | **`restore` 重掷 RNG，SL 语义被破坏** | 致命——训练结果全假 | 中 | `docs/01` §1.6 测试 2 进 CI；生产构建里让"重掷"不可达 |
| 13 | **战斗层没有人类数据** | 中——无法做战斗 BC | 已确认 | 规则 bot 冷启动 + 束搜索方案（`docs/04` §4.3）；挖 `has_replay` |
| 14 | 许可证限制 | 中——不能商用 | 中 | spire-codex 为 PolyForm Noncommercial 1.0.0，仅限非商用；逐个确认依赖许可 |

## 5.4 里程碑与验收标准

> ⚠️ **本节是早期草案，保留作历史参考。**
> 其中"对拍 ≥90% 通过""≥5k 步/秒"这类**定量门槛已经作废**：
> [`docs/13`](13-实施规划与当前缺口.md) 明确要求**严格确定性用例不设"90% 对就够"的门槛**，
> 且吞吐必须实测（不沿用目标值当真）。**以 `docs/13` 的 M0–M5 与工单表为唯一口径。**
> 下面各阶段"交付/验收"的**方向**仍然有效，只把数字当参考。

每阶段**必须**通过验收才进入下一阶段——这是防止"带着 bug 往前冲"的唯一手段。

### M0 · 模拟器骨架
- **交付**：1 角色 + Act 1 + 80–120 张卡 + 15–25 怪物 + 20–30 遗物；完整 run 循环；`snapshot/restore`；`replay(seed, actions)`
- **验收**：真机回放对拍逐帧一致（≥10 局）；单卡/单怪测试全绿；≥5k 步/秒/核
- **风险**：数值对齐耗时可能超预期 → 先做核心 30 张牌打通链路

### M1 · 接口与基线
- **交付**：观测投影函数 + 反作弊测试套件；gym 风格 env（含 action mask）；`render_text()`；规则 bot
- **验收**：CI 全绿（含影子对局与归因测试）；规则 bot 稳定打到 Act 2
- **意义**：到这里为止**没有任何机器学习**，但项目已经立住了

### M2 · 战斗层（固定牌组）
- **交付**：BC 冷启动 + PPO 训练脚本；向量化采样
- **验收**：测试遭遇胜率 >95%；平均剩血超过规则 bot；行为审查无明显怪招

### M3 · 战斗层泛化
- **交付**：随机牌组训练 + 课程 1–5 级
- **验收**：held-out 牌组上保持优势；连续战斗（课程第 5 级）表现显著优于单场训练版本

### M4 · Run 层
- **交付**：MC 牌组评估器 → `V_run` 蒸馏 → 完整 run 端到端
- **验收**：完整 run 通关率超过规则 bot 一个量级；选牌决策一致率达标

### M5 · 真机验证
- **交付**：真机桥接（基于社区 mod 协议）+ 评估脚本
- **验收**：sim2real 动作一致率 >95%；真机通关率与模拟器差距在可接受范围

## 5.5 许可证与合规（必须在 M5 前处理完）

| 事项 | 具体要求 |
|---|---|
| **不分发游戏资源** | 不打包任何美术、音频、原始文本资源。数据表按公开来源（wiki / 社区 API）重建 |
| **核实依赖许可** | 各社区项目许可不同（有的标 `NOASSERTION`），**使用前逐个确认**允许什么、是否要求署名、是否传染 |
| **不修改游戏文件** | 真机对接只做"读状态 + 注入输入"，走官方支持的 mod 机制 |
| **只做单机** | 不接入多人联机（会被判定为作弊，且可能造成 desync） |
| **数据来源合规** | 使用社区 run 数据前确认其采集与再分发条款 |

## 5.7 已确定的设计决策（决策记录）

| # | 决策 | 理由 | 状态 |
|---|---|---|---|
| D1 | 自建高度抽象的纯数值模拟器，不做美术/动画 | 训练效率优先；机制与表现层解耦 | ✅ |
| D2 | 利用社区整合的机制数据，~~不自行反编译 `sts2.dll`~~ | ~~边际收益远低于成本~~ | ❌ **已作废** |
| D3 | 社区数据必须经过**导入 + 校验**，不直接信任 | 版本漂移、覆盖不全、转写错误 | ✅ |
| D4 | 分两层（战斗层 / Run 层），先训战斗层 | 时间尺度差一个数量级，稀疏奖励不可端到端 | ✅ |
| D5 | 观测 = 人类可见信息，用类型系统强制隔离 | 硬约束；也是 sim2real 的前提 | ✅ |
| D6 | 不用 LLM 作策略主体 | 延迟、采样成本、无法证明信息隔离 | ✅ |
| D7 | 先写规则 bot，再做 ML | 基线、数据源、模拟器压力测试 | ✅ |
| **D8** | **不从头写规则引擎**，评估现有开源模拟器后选基座，只重写观测/动作接口 | `docs/07` §7.1 证明接口设计是关键，规则实现可复用 | ✅ |
| **D9** | **训练 SL**；重开是获取牌序的**唯一**渠道；`restore` 必须保留隐藏 RNG | 用户明确要求；这是本文档的形式化基础 | ✅ |
| **D10** | 信息三级分类：L1 固定知识（允许，含记忆）/ L2 已揭示（允许）/ L3 未揭示（禁止直接读取） | 用户明确要求："随机数不是禁忌，未揭示才是" | ✅ |
| **D11** | 战斗层主方案 = **束搜索 + 价值网络**，纯策略网络降为消融基线 | "蒸馏进网络"有六次公开失败；零神经网络方案反而拿到 52% | ✅ |
