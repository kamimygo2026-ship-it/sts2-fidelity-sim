## 四条硬约束

| # | 约束 | 含义 | 落地机制 |
|---|---|---|---|
| 1 | **不读取随机数** | 信息按三级分类：**L1 固定知识**（卡牌数值、怪物 AI、敌人意图）允许，含编码进权重；**L2 已揭示的随机结果**允许；**L3 未揭示的随机结果**（剩余牌序、未来掉落、敌人行动队列）**禁止直接读取** | 单一投影函数 + 类型级隔离 + 反作弊 CI（见 `docs/01`） |
| 2 | **训练 SL** | 允许重开，但**重开是获取牌序的唯一渠道**。于是"何时重开"成为一条独立的策略头 | `restore` 保留隐藏 RNG + meta-episode 形式化（见 `docs/01` §1.4） |
| 3 | **像人一样** | 在卡牌奖励、出牌、地图、商店上做出人类可理解的决策 | Run 层用真实人类数据做 BC；战斗层用搜索 + 价值评估（见 `docs/04`） |
| 4 | **抽象模拟器** | 复刻机制与数值，不复刻表现层 | 复用社区引擎 + 数据驱动内容 + 真机回放对拍（见 `docs/02`、`docs/07`） |

> 约束 1 的要害不是"不调用 RNG"——模拟器当然要调 RNG。要害是：**已经掷出但还没翻开的骰子不能被看到**。判定标准是"人类的屏幕上有没有出现过，或者人类能不能稳定记住"。

**SL 与 NoSL**：尖塔社区有两种对局规范——NoSL（不知未来牌序、不能重开）与 SL（可通过重开逐步观察出牌序）。本项目训练 **SL**，但**必须同时报告 K=1（不允许重开）的胜率**，它是判断 agent "学的是牌理还是刷牌序"的唯一手段。

## 时间尺度：为什么必须分两层

这是整个架构的出发点。两类决策的频率差一个数量级，信用分配跨度差两个数量级。

| 层 | 决策内容 | 每局次数 | 单次影响 | 奖励信号 |
|---|---|---|---|---|
| **战斗层** | 出牌、目标、药水、结束回合 | 200–500 | 小，可逆性中等 | 密集（一场战斗的胜负与剩余 HP） |
| **Run 层** | 卡牌三选一、地图选路、商店、营火、事件 | 50–100 | 大，几乎不可逆 | 极稀疏（通关/死亡，几百步后才知道） |

结论：**先训战斗层（信号密），再用它当 Run 层的评估器**。不要一上来做端到端全流程 RL，稀疏奖励会让你怀疑人生。

## 铁律

1. **一切机制以源码为准；所有断言与猜测都必须经源码检验。**
   数值与行为**都**从 `data/decompiled/sts2/` 取；JSON 只提供 id、类名与结构，不提供数值
   （社区库落后至少一个补丁：实测 651 个变量里 37 个不一致）。每条机制声明要标出
   `文件:方法名`，每个断言要能追溯到源码行。**写之前先读源码，不要用"按常理应该是"补。**
   完整规则、可判定要求与 8 个实测踩坑见 `docs/09` §5。
2. **先有规则 bot，再有神经网络。** 没有基线的 RL 是盲人摸象。
3. **先小后大。** 1 角色 1 幕 100 张牌跑通端到端，比 5 角色 4 幕的全量模拟器有用得多。
4. **数值不对齐的模拟器 = 在训练另一个游戏。** 对拍测试是可信度的唯一来源。
5. **能排除的内容就排除。** 机制存疑的卡先不纳入训练集，好过让模型学错。
6. **测试必须能分辨好坏，而不只是分辨对错。** 一个只会证明"程序没崩"的套件价值接近于零。
   每条新机制都要做**反向验证**：故意改错，确认测试会失败。
7. **解析不了的东西要报出来，不能静默丢弃。** 静默丢弃 = 模型学到一个错误的定义且毫无信号。
8. **覆盖率必须可数。** `python tools/content_status.py` 一次打印每个内容类别的
   总量 / 引擎真的能跑 / 还差什么；缺口要落到"哪个文件、哪个钩子、影响多少个对象"。
